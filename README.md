# QuizMake

問題セットを作成・整理し、4択クイズと復習を行う学習アプリです。Web/PWAに加え、Capacitorを使ったAndroid・iOSビルドに対応しています。

## 主な機能

- フォルダと問題セットの作成・編集・並べ替え
- JSONまたは貼り付けによる問題の一括取り込み
- ChatGPT向け問題作成テンプレートのコピー
- Markdownと表に対応した詳細解説
- 正解・不正解・曖昧を記録する4択クイズ
- 問題セット単位の復習と学習状況表示
- カテゴリ別の手書きノート
- 50問回答でごはん・おやつを各1個獲得し、既存の応援キャラのお世話・芸の練習
- 端末内JSONバックアップ
- 任意のSupabase同期（8文字の一時接続コード対応）
- スマートフォン、タブレット、PCに対応した明るいレスポンシブUI

## キャラのお世話

ホームのキャラをタップすると、名前・なかよし度と「ごはん／なでる／おやつ」を表示します。外見の成長・進化や家具集めは行いません。全身を描いた連続コマで、まばたき・しっぽの揺れ、座る・耳をかく・立つ・伏せる・寝る動作を再生します。頭・耳・胴体・足を分割して変形する方式は廃止しました。なかよし度による自然な反応と、くるりん・タッチ・おじぎ・ごろん・おやすみも全身のコマで表現します。

コマ順と時間は [companionAnimation.ts](src/utils/companionAnimation.ts)、描画は [companionFrames.ts](src/components/companionFrames.ts) にまとめています。完成した全身コマを前足の接地中心で揃え、座った位置がしっぽや耳の動きでずれないようにしています。位置の基準は [companionFrameLayout.ts](src/utils/companionFrameLayout.ts) に保存しています。座り姿の小さな変化は画面の更新頻度に合わせてなじませ、各コマの境目で減速せずに動かします。動作を切り替えるときも直前に描いた姿を引き継ぎ、体の不透明度を保ちます。姿勢が大きく変わる芸はコマを重ねず、再生間隔を短くして二重の顔や足を防ぎます。部位の伸縮・回転は行いません。練習中は間を置いてゆっくり再生し、習得後は通常のテンポになります。芸のご褒美のタイミングも動作の長さに合わせています。育成画面の操作欄をスクロールしても、キャラの全身は表示したままです。操作説明や操作後のセリフは表示せず、キャラの反応と必要な残数・習得度を表示します。

動作素材はImageGenの組み込みツールで元のキャラを参照して作成しました。[frames-v3](src/assets/companion/frames-v3) に8種類のシート、生成プロンプト（`.prompt.txt`）、透過PNG原本（`.source.png`）と全身コマの切り出し情報（`manifest.json`）を保存しています。実行用WebPは全身単位で切り出し、シートごとに一定の縦横比で縮小し、足元を揃えて圧縮したものです。生成時に左右の足が入れ替わったコマなどは再生から除いています。画面外・非表示タブでは描画を休止し、同じコマは再描画しません。OSの動きを減らす設定では、各動作の代表となる全身1枚を表示します。

保存済みの回答50件につきごはん・おやつ各1個を自動獲得します。不正解・復習も対象とし、回答IDを保持して再集計・再表示・削除後の復元による重複獲得を防ぎます。既存の回答履歴も初回に集計します。旧20問ルールで獲得したごはんと回答の端数は保持し、移行後は50問ごとに獲得します。端数は翌日へ持ち越し、ごはんとおやつは期限なく保管します。旧データからの移行時に限り、残っているごはんと同数のおやつを初期付与し、既存のごはん・なかよし度・芸は保持します。演習結果では今回獲得した個数をまとめて表示します。履歴を保存しない公開教材のお試しは対象外です。

初期バランスは [companionCare.ts](src/utils/companionCare.ts) にまとめています。

| 項目 | 初期値 |
| --- | --- |
| ごはん1個 | なかよし度 +4 |
| 芸の練習1回・おやつ1個 | 習得度 +1回、なかよし度は変わらない |
| なでる | +0.5、1日3回まで加算（反応は何度でも） |
| 会わない期間 | 2日間は低下なし、3日目から1日 −1 |
| 以前の最高なかよし度への回復 | 上昇量2倍、最高値を超えた分は通常の上昇量 |
| なかよし度の上限 | 100 |
| 芸の解放 | なかよし度に関係なく最初から5種類 |
| 芸の習得に必要な練習 | 5 / 8 / 10 / 12 / 16回（順に、くるりん／タッチ／おじぎ／ごろん／おやすみ） |

芸5種類をすべて覚えるには、おやつ51個・2,550問が必要です。最初の50問で芸が1回分進みます。なかよし度が低下しても解放済みの芸・習得済みの芸は失わず、習得後はおやつ不要で何度でもお願いできます。会った日・なでる上限の日付にはアプリの学習タイムゾーンを使います。

育成データはアカウント別のIndexedDBに保存し、既存のバックアップ・同期対象に含めます。ごはんとおやつの消費・芸の習得度・なかよし度は一括保存し、保存失敗時にはすべて保持します。複数端末で競合した場合は既存の同期の確認手順で育成データを選びます。

専用テストは `npm run test:companion`。ブラウザの合成データによる操作テストは、開発サーバー起動後に `QUIZMAKE_PLAYWRIGHT_MODULE` をPlaywrightのディレクトリに設定して `node tests/browser/companion-care-validation.mjs` を実行します。
連続動作と全身表示の確認は、追加で `QUIZMAKE_SHARP_MODULE` をSharpのディレクトリに設定し、`node tests/browser/companion-animation-validation.mjs` を実行します。確認用GIF・全身コマの一覧・足元の位置の計測結果・スマホ幅のスクリーンショットを `tmp/companion-smooth` に保存します。

## グループへの公開と進捗

グループへの公開時は、公開元の教材で既に学習したレベル別問数・解答数をグループの進捗に反映します。元の問題・回答履歴は保持し、取り込み用の複製は作りません。その後の演習でも、回答の端末保存を確認してから集計を更新します。公開版と一致する問題を対象にし、共有をOFFにした教材や別の集計元を選んだ設定は保持します。

集計処理は [groupLearningReflection.ts](src/utils/groupLearningReflection.ts)。グループごとの既存の共有設定・公開版・会員資格を確認し、レベル別問数と解答数だけを送信します。再試行は集計値を置き換えるため二重加算されません。既存APIを使い、データベースの変更はありません。

正常に反映できた公開処理は画面から消え、追加画面も閉じます。処理中・失敗・再反映が必要な処理は確認と再試行ができます。演習結果で反映に失敗した場合も、個人の学習記録を保存したまま再試行できます。

`tests/group-learning-reflection.test.mjs` で集計と設定保持、`tests/group-learning-rls.test.mjs` で実際のSQL権限を確認します。画面操作はPlaywrightのディレクトリを `QUIZMAKE_PLAYWRIGHT_MODULE` に設定し、`node --import ./tests/helpers/typescript-imports.mjs tests/browser/group-community-validation.mjs` で確認します。

## 検証とビルド

```bash
npm test
npm run build
npm run build:native
```

通常の修正では関係するテストファイルだけを実行し、配布前には `npm test` を実行します。保存・復元・同期競合・認証／権限・取り込みの互換性を優先し、文言・CSSクラス・固定ピクセル値だけのテストは追加しません。見た目、スクロール、スワイプは変更した画面をスマホ幅で確認します。削除したテストと理由は [テスト整理記録](tests/AUDIT.md) にあります。

ネイティブプロジェクトへ最新のWeb資産を反映する場合は、次を実行します。

```bash
npm run mobile:sync
```

ストア提出手順と確認項目は、[store/release-checklist.md](store/release-checklist.md) と [store/native-build.md](store/native-build.md) にまとめています。

## クラウド同期

Supabase同期を有効にする場合は、ビルド時に次の環境変数を設定します。

```text
VITE_SUPABASE_URL
VITE_SUPABASE_ANON_KEY
```

未設定でも、端末内での問題作成・学習・JSONバックアップは利用できます。データベース変更は `supabase/migrations`、回帰検証用SQLは `supabase/tests` にあります。

Web/Androidの配布CIでは公開キーの検査を行います。リポジトリ変数 `QUIZMAKE_EXPECTED_SUPABASE_PROJECT_REF` を設定すると接続先も固定検査します。これはアプリへ埋め込む環境変数ではありません。キーの権限・URLとの不一致は配布前に停止しますが、ログインの実機検証は別に必要です。

専用Supabaseへの移行準備は [分離手順](docs/supabase-separation-runbook.md) を参照してください。現在のmigrationフォルダを新環境へ一括適用しないでください。
