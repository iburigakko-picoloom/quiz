# 単一レコードのサイズ超過：停止・診断・復旧

この変更は、送信上限を超えるレコードを端末に保持したまま同期を停止し、対象の種類と計算サイズを表示する。大きなレコードを送信可能にする分割処理は、別の変更で実装する。

## 確認できた原因

公開済み e57523d73dde9eb68133d4abdaf4648ae03a474d は、送信バッチの準備中にサイズ超過を通常の Error として返していた。同期監視はこれを unexpected と判断するため、通信を行っていない同じ失敗を自動再試行していた。

単一操作の従来の計算値は UTF8(JSON.stringify(operation)) + 1。バッチはさらに 2 バイトから計算を始めるため、単一操作の計算値が 921599 または 921600 の場合は、例外も送信バッチも作られず、未送信データが残ったまま done を返す経路があった。

| 単一操作の従来の計算値（B） | 修正後 |
| --- | --- |
| 921598 | 1 操作のバッチを確定 |
| 921599 | payload_too_large で停止、原本を保持 |
| 921600 | payload_too_large で停止、原本を保持 |
| 921601 | payload_too_large で停止、原本を保持 |

クライアント上限は 900 KiB（921600 B）のまま。表示する「計算サイズ」は、操作の UTF-8 JSON、区切りの余裕 1 B、配列の余裕 2 B を含む既存の保守的な計算値で、HTTP 全体のサイズではない。

サーバー側の既存 SQL（20260929223301 のマイグレーション）は、バッチを最大 500 操作、p_operations::text を最大 1048576 B に制限する。JSONB での表現差や RPC の枠もあるため、クライアント上限を引き上げて回避しない。この変更に SQL・RLS・本番データの変更はない。

## 保全と診断

- 種類は固定ラベルだけを使う。教材名、問題文、回答、実 ID、ユーザー情報、認証情報は表示しない。任意のサーバー文言は表示許可しない。
- サイズ超過は push_prepare / payload_too_large で停止し、未来の再試行時刻を設定しない。手動再試行の操作は残す。
- バッチ準備のトランザクションを中止し、端末のレコード、送信待ち操作、内容、操作 ID を維持する。既存の応答未確認バッチは、本文・ID を変更せず再利用する。
- 前回の成功時刻を新しい成功として更新しない。空のバッチ確定直後に保存された変更がある場合も more を返す。

## 再現と検証範囲

境界値、日本語 UTF-8、停止とタイマー、成功時刻の保持、小さい操作と大きい操作の同居、応答未確認の再送原本、バッチ確定直後の保存、診断の情報制限を実際の IndexedDB 相当・同期エンジンで検証する。tests/record-sync-size.test.mjs を全体テストと同期テストに登録した。

ブラウザー確認用には、実装の snapshotTargets と parseStudyPlan で生成・検証した 695 問の合成計画を使う。ユーザーの実データや実アカウントは使わない。親側が読み取った Android のサイズ超過メッセージは原因経路の証拠だが、その端末で肥大化したレコードの種類は未確定。

同期画面を表示したまま手動再試行し、正常な空の Pull を返す合成ブラウザーケースでは、Pull 適用を繰り返し、バッチ確定に到達しない別の挙動が確認された。設定一覧から既存の再試行イベントを起動するとサイズ超過で停止する。前者はこの変更では未修正で、同期画面からの再試行の合格とは扱わない。実機のサイズ超過の原因と、この別の再現条件を混同しない。

## 無損失分割の次段階

学習計画は対象問題と内容版を固定したスナップショット、手書きノートは画像を含むため、正当な内容でも単一レコード上限を超え得る。次の変更では、元の内容を切り捨てず、異なるキーの分割レコードと、版・個数・サイズ・ハッシュを含むマニフェストを使う。

分割の完了・内容検証前にはマニフェストを公開・反映せず、すべての部分を検証してから原子的に復元する。CAS、送信 ID、オフライン保存、再起動、競合、バックアップ復元、削除を維持する。同じキーの断片送信は上書きされるため使わない。応答未確認の既存バッチも書き換えない。
