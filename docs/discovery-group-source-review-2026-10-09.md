# 「見つける」とグループ共有元の修正レビュー

2026-10-09。既存の資料同期修正 `c103d3554748d0f00b43a102ee7f67b8307d7c87` を基点に、独立したブランチ `codex/discovery-group-link-20261009` で実装した。ユーザーから本番公開の明示承認を受け、最終レビューと試験後に既存のGitHub Pages手順で公開する。公開コミット・CI・配信照合は公開検証記録で確認する。

## 既存モデルと原因

### 「見つける」の末尾

`Layout` の `.app-layout__scroll` は高さを制約された縦方向の flex / scroll 領域である。その子 `.public-screen` は既定の `flex-shrink: 1` と `min-height: 100%` を持ち、長い一覧が子の箱からあふれる。末尾の余白は箱の末尾に付き、実際の最終行まで付かない。固定下部ナビ（76px と safe bottom）に最終行や「もっと見る」が隠れた。

修正前の隔離ブラウザでは6サイズ×2一覧の12条件中9条件で末尾の操作がナビに隠れた。これはコード上の再現であり、ユーザー端末そのものの観察結果ではない。

`.public-screen` の縮みを止めて内容の高さを保ち、既存のナビ・safe area 分の余白が実際の末尾に付くようにした。見出し・検索・タブ・行内余白・図版を小さくし、タップ対象は44px以上を維持した。

### 共有者の元教材

クラウドには既に `shared_problem_sets.owner_id / local_set_id / current_version_id` と `quiz_group_problem_sets(group_id, set_id)` がある。後者の主キーは重複を防ぐ。公開時のローカル教材には従来 `cloudSetId / visibility` だけを反映していた。グループ進捗の候補と集計は `sourceSetId / sourceVersionId / sourceManifest` を持つ取り込みコピーを前提とし、所有者自身の元教材を扱えなかった。

新しい `publicationSource` は所有者の元教材と公開ID・公開版・既知の共有先を結ぶ。従来の取り込み履歴を表す `source*` とは別の情報であり、取り込み済み教材を再公開しても元の履歴を消さない。

対応情報の保存は共通公開キューを使うグループ・単独公開・公開フォルダへの公開に適用する。既存の共有先ペイロードを変更せず、新たな宛先を追加しない。「共有元を開く」の表示と元教材を選ぶ進捗欄はグループ内の所有者教材に限定する。過去の共有も、サーバーの所有者・元セットID・公開IDと端末の元教材が一致すれば、現在の公開版からメモリ上で対応を導出できる。一括書換えによるバックフィルはしない。元教材や公開IDを失っている場合は推測して紐づけない。

| 記録 | 場所と扱い |
| --- | --- |
| 元セットID | 既存 `ProblemSet.id`。クラウドの `shared_problem_sets.local_set_id` と照合し、変更しない |
| 公開ID・所有者・版 | 元セットの `cloudSetId` と `publicationSource.setId / ownerId / versionId`。サーバーの現在の所有者・版を確認する |
| グループID | `publicationSource.groupIds` は確認できた追加先の重複のない記録。現在の権限・配置の根拠はサーバーの `quiz_group_problem_sets` と会員資格 |
| 一グループの共有解除 | サーバーの関係が消えたグループで読取・更新RPCが拒否される。ローカルの既知グループ記録が残っても権限を付与しない。他グループの同意や共有を変えない |
| 全共有解除・元教材削除 | 全共有解除の既存コールバックは対応情報と `cloudSetId` を消し、教材と履歴を保持する。元教材削除後の完了反映は警告で停止し、元教材を復活させない |
| 単独公開・フォルダ公開だけの解除 | 既存の宛先単位解除を使う。他のグループで共有が続く教材の対応情報は保持する |
| 複数グループ・再試行 | 一つの元教材に既知の追加先を併合し、同じ反映なら元データをそのまま返す。古い完了ジョブは現在の公開版を確認し、過去の版へ戻さない |
| 進捗共有 | `(group_id, set_id, user_id)` ごとの本人同意・generation・公開版の一致が必要。対応情報の保存とは別処理 |

## 実装とデータ保全

- 公開の完了反映時に現在の認証済み公開スナップショットを読み、所有者とローカル教材IDを確認して対応情報を保存する。古いキューの再実行は現在の公開版を使い、過去の版へ戻さない。保存前後にアカウント境界を確認する。
- 元の教材・問題ID・フォルダID・進捗・回答履歴は保持する。元教材が削除済みなら再作成せず、公開済みキューの端末反映警告として扱う。再試行で重複公開しない。
- 公開内容を正規化して SHA-256 で照合する。本文・説明を対応情報に二重保存せず、私的な画像・注釈・回答内容を公開ペイロードや照合情報へ追加しない。
- 対応表が400KiBを超える場合は公開ID・版の小さなポインタだけを永続化する。詳細画面と自己集計では、閲覧権限がある現在の公開版を取得してメモリ上で照合する。自己集計の追加読取は直列に行い、取得中・失敗時は不完全な数値を表示しない。
- 既存の所有者教材も、現在のサーバー上の所有者・ローカルID・公開ID・問題IDが一致すれば、詳細画面で対応を導出できる。再取り込み・再公開・データ書換えは不要。
- 所有者の元教材を候補の先頭にし、重複コピーがあっても一つを選んで集計する。グループ詳細の主ボタンは該当する元教材の「共有元を開く」となり、そのローカルIDを開く。他のメンバーの取り込み操作は従来どおりである。
- 進捗共有は既存の本人同意を必要とする。新たな共有・取り込み人数は自動で記録しない。他の人の同意や集計を書き換えない。照合できない追加・編集・削除された問題は、公開版の不変の分母を保ち、同じ内容の問題として誤集計しない。
- `groupIds` は既知の追加先の記録であり、権限や現在の配置一覧の根拠にしない。実際の共有・閲覧・会員資格・削除はサーバーの現在の関係とRPCで判定する。全公開を取り下げた時は対応情報を消す。
- バックアップ・同期の正規化は対応情報を検証して保存する。旧データは新フィールドを要求しない。今回の機能で本番DBのスキーマ変更・実データ修復は行わない。

SHA-256 は固定依存 `@noble/hashes 2.4.0` の `sha2.js` を使用する。既存のサーバー `content_revision` の PostgreSQL JSON文字列表現とは別のクライアント照合値である。ローカルと公開スナップショットを同じ正規化で比較する。Node標準SHA-256との一致、Unicode、公開内容編集、私的画像の除外を試験する。[公式実装と使用方法](https://github.com/paulmillr/noble-hashes)

## 公開状態と未確認範囲

公開はユーザーの明示承認に従い、mainの通常pushから既存の `deploy.yml` を実行する。公開前の本番は `c103d35`、GitHub Actions `37890031902` の成功版である。今回の差分にDBマイグレーション、認証設定、共有先拡大、資料修復SQLはない。元リポジトリの既存未追跡ディレクトリと旧作業ツリーを保持し、古いSQLタスクを再開しない。株AIのプロセスやガードは操作しない。

同じ担当者が実装時とは別に、権限境界、非同期保存と同時編集、公開版の不変性、同期サイズと旧データの互換性の観点から差分を読み直した。保存直前に最新の `dataRef` からメタデータ差分を作り、既存の保存予約・revision保護を使うことを確認した。進捗の送信RPCには現在の認証者・所属・共有関係・本人同意・generation・公開版・分母のサーバー検査がある。元教材の対応情報だけで他人の読取や更新権限を作らない。正規化は不正な対応表を拒否し、旧データに新フィールドを要求しない。既存の資料・画像・回答履歴・競合・中断再開・バックアップの全回帰も検証する。

ブラウザ試験は既存のコード用Playwright環境に新しい一時プロファイルを作り、127.0.0.1と試験APIで実行した。ユーザーの実ブラウザ・認証済み端末への接続は利用できず、実端末の再読込・未保存入力・同期には触れていない。OSの実キーボード、実ブラウザのバー伸縮、実機のsafe areaは未確認であり、390×390の縮小領域とCSSのsafe area模擬をその代用として明記する。

50,000問の実機描画・追加読取の速度、ネットワーク不良時の大量所有教材一覧は未実機確認。大きな対応表は永続化しないため、自己集計に追加の認証付き読取が必要になる。失敗時は理由を表示して再読み込みを促し、既存教材や履歴を削除しない。実端末確認は配信確認と区別する。
