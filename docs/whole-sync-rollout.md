# 全体同期と端末内復旧コピー

この変更は段階実装中です。画像コピー・資料参照の削除保護・完全ファイル復元は実装済みです。全体の競合判定、レコード転送の一時保存／最終確定SQLは隔離テスト用に用意しています。二択画面と既存自動同期への接続は別途検証します。全体同期を本番で有効化したとは扱いません。

## 保存と復旧

- 問題集コピーは問題IDと画像IDをそれぞれ新規発行し、同じ画像バイト列を新しい所有者へ保存します。問題・画像Blob・同期Outboxは同一トランザクションです。画像削除は問題IDと画像IDの両方で所有者を確認します。
- 別の問題集に参照されている資料を持つ問題集は削除前に止め、参照元の教材名を表示します。対象をまとめて削除する場合は、その中だけの参照は妨げません。
- 新しいJSONバックアップには画像本体、SHA256、問題・ノート・画像の収録数、全体の検証用ハッシュを含めます。取得できないノート、画像、PDF、参照資料は欠落一覧と「部分」の表示を付けます。部分コピーは完全復元として上書きできません。
- 完全ファイルのメタデータ上限は既存レコード同期の128 MiBです。旧Snapshotの通信上限32 MiB、個別PDF・画像の50 MiB上限は維持します。25 MiBのPDFがbase64で32 MiBを超える入出力も検証しています。
- 完全ファイル復元は問題、ノート、画像、計画・メモ・設定、復元前コピーを既存の共通IndexedDB内でまとめて確定します。ネイティブlocalStorageへの投影は再起動後も再実行できます。古いファイル形式の従来復元経路は、この原子的な復元保証の対象外です。
- 復元前コピーはこの端末の一覧から読み出し・復元・書き出し・明示削除できます。同内容は重複保存しません。最初の実測コピーと入れ替え対象の大きい方の4倍、かつその時の空き容量の半分以下を保管枠とします。以後、全コピーを利用者が削除するまで枠を維持します。コピー作成には少なくとも作成サイズの2倍の空き容量を要求し、既存コピーを自動消去せず、上限または実際の保存エラーで入れ替えを止めます。普通の自動同期はこの履歴を増やしません。
- 学習データの実編集世代はIndexedDBに保存します。受信、送信確認、PDF・画像送信の準備、チャンク作成・廃棄、移行によって世代を増やしません。端末の時刻や`commitId`は競合の勝敗に使いません。

## 本番適用の個別承認が必要なSQL

対象候補: `supabase/migrations/20261005154212_quiz_whole_commit.sql`。**未適用**です。以前に承認されたアカウント同期設定SQLの承認範囲には含めません。

この候補は既存の`private.quiz_sync_heads`にモードと保存端末・反映時刻を追加し、既存のレコードと操作UUID領収書を使います。新しいhead基盤、端末分岐台帳、クラウド全件復元履歴は作りません。

一時パーツは所有者のみが限定RPCで書けます。1パーツ1 MiB／500件、1確定512パーツ／200,000件までで、所有アカウント全体の一時JSONは256 MiB以下です。最終ライブメタデータは既存のアカウント128 MiB上限です。途中のパーツは受信側に見せず、全パーツのハッシュ・件数・キー一意性とサーバーrevisionを検証してから一度だけ確定します。ライブ状態に含まれない既存レコードは削除情報になります。確定後にパーツを削除し、小さい再送領収書を残します。未確定の一時データは1時間で期限切れとなり、当該教材データの次回開始または明示中止で破棄できます。

所有者が有効化した同期データだけ、旧レコードpush/pullと旧Snapshot書き込みをサーバーで拒否します。未有効化の同期データは従来の動作を保ちます。以前の送信結果が不明な場合は、既存UUIDの一致した領収書を読み、保護を回避して旧書き込みを実行しません。

新RPCはpublicの`SECURITY INVOKER`とprivateの所有者確認付き`SECURITY DEFINER`に限定します。どちらも空の`search_path`です。`authenticated`だけに必要な実行権限を付け、`anon`・`PUBLIC`・`service_role`からは剥奪します。既存のprivateテーブルのRLS・直接アクセス権は拡大しません。Auth設定、実回答、教材公開範囲、グループ共有同意、Storageの公開権限は変更しません。

実測では本番の最大レコード生データが24,388,172 bytes、従来Snapshot再構成が25,383,713 bytesでした（2026-10-05、ID・本文を取得しない集計）。そのため32 MiB Snapshotへ全体を詰め替えず、128 MiBの既存レコード容量を保つ転送境界を用います。

## 戻し方

1. 新クライアントの有効化を止めます。未有効化の同期データは従来クライアントへ戻せます。
2. 有効化済みデータのhead・レコード・UUID領収書・旧書き込み拒否は維持します。古いクライアントへ単純に戻して拒否を外すと、全体の選択をレコード単位で混合する恐れがあるため、勝手に外しません。
3. 必要に応じて、所有者の完全な端末内復旧コピーと現在のクラウド全体を比較し、当該同期データ単位で互換クライアントを用意してから切り替えます。データ削除、SQL DROP、RLS緩和、全アカウントの一括書き換えは戻し方に含めません。
4. 前回適用済みのアカウント設定SQLは、リポジトリ時刻と本番登録時刻が異なります。`supabase db push`等で再実行せず、履歴の対応を確認してから、この個別SQLだけを承認された手段で適用します。
