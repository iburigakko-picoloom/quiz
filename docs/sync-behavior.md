# 同期の判断と高速化

## 自動同期

- サーバーの更新リビジョンと、最後に共有できた内容の SHA-256 を基準にする。端末の時計で上書き方向を決めない。
- 端末だけの変更は従来の自動保存キューで送信する。サーバーのリビジョン照合（CAS）は維持。
- クラウドだけの変更は、自動同期 ON・ホーム表示中・作業やダイアログがない場合に取り込む。演習中や編集画面では置き換えない。
- 両方が異なる内容へ変わった場合、または共通の同期履歴が不明な場合は確認を残す。同じ内容へ変わった場合は同期済みにできる。
- 古い端末の短いハッシュだけでは自動取り込みを許可しない。一度内容が一致することを検証するか、手動で同期を完了してから新しい基準を使う。
- 取り込み直前にも、保存待ち・他タブの変更・同期先・端末の SHA-256・画面状態を確認する。復元用バックアップと失敗時のロールバックを維持する。
- 成功したデータと同期基準は同じ同期操作内で確定し、表示データを読み直す。通常の取り込みでページ全体を再起動しない。

## 今回削減する処理

- 同期済みの状態確認：小さい認証付きメタ情報だけ取得。本文を再ダウンロードしない。
- 保存後の確認：サーバーが返した検証済み本文を使い、リビジョンが変わっていないか確認する。
- PDF：起動をまたいでも端末の PDF がサイズ・SHA-256 と一致すれば再利用。異なるものだけ取得する。
- 資料・メモ：IndexedDB の一つのトランザクションで変更・追加・削除を適用。同じ内容は書き直さない。設定等の localStorage も同じ値は書き直さない。
- 起動・復帰・ホームに戻った時に確認。フォーカス等の重複イベントは5秒間まとめ、前面表示中は60秒ごとにも確認する。

## 未実装の範囲

問題・解説・学習履歴を含む本文 JSON の通信と AppData の保存、復元用バックアップはまだ全体単位。完全なレコード単位の差分通信ではない。
次段階では、削除記録・取得カーソル・サーバー側の原子的な確定・旧クライアントとの互換性を備えた差分プロトコルを追加する。現在の保存形式は変更しない。

## 回帰確認

`protected-work` / `sync-revision` / `sync-rpc` / `storage-sync-state` の既存テスト内で、競合判定、旧ハッシュ衝突、取り込み中の編集開始、接続変更、PDF 再利用、資料の差分保存、認証失敗を検証する。
