# Phase 2: 学習セッションのタイムライン

## 実装

- グループのタイムラインに名前・アイコン・教材名・学習日時・解答した問題数を表示。教材名からPhase 1の共通進捗詳細へ進み、元のタブへ戻る。
- 活動共有は進捗共有とは独立した明示同意。初期OFF。グループ内の確認ボタンで共有する範囲を表示し、同意後の学習だけを対象にする。
- 演習結果・画面退出時に保存済み回答を教材単位に集約。未保存の回答、公開版とrevisionの異なる回答、共有元のオリジナル、プレビューは対象外。1問ごとの投稿を作らない。
- 安定したsession event IDは保存済みanswerLog ID集合のSHA-256。ID、回答内容、選択肢、正誤、質問文、メモ本文は送信しない。送る内容は教材・公開版・コピーの識別子、日時、ユニークな解答問題数、opaque event IDのみ。
- アカウント別IndexedDB outboxに先に保存。ネットワーク失敗後も再送可能。演習開始時のアカウントと終了時のアカウントの一致を要求する。起動・復帰・オンライン復帰・タイムラインの再試行で送信。
- サーバーに同意を確認する最初のRPCは教材IDだけ。OFFや同意前の活動については数値payloadを送らない。
- 一覧は50件ずつのkeyset pagination。教材ごとの読み取りループを行わない。
- Phase 1で追加した小さいグレーの補足説明は整理し、必要な共有同意は通常の文字サイズで表示。

## DB

`20261107150102_group_session_timeline.sql` は追加のみ。

- private.quiz_group_activity_consent: グループ/利用者単位のenabled・generation・enabled_at。
- private.quiz_group_activity: セッション別の最小集計。group/user/set/eventのunique制約で同期・再送を重複させない。
- RLS有効、テーブル直接アクセスをPUBLIC/anon/authenticatedから剥奪。内部security definerは空search_pathとauth/現メンバー確認を持ち、publicのsecurity invokerラッパーはauthenticatedのみ実行可能。
- 既存record_problem_set_copyは公開教材だけの認可だったため、現在の共有グループのメンバーにも許可するよう修正。利用者単位の取り込みカウント重複防止を維持し、端末ごとのlocal copy ID一致は活動の認可に使用しない。
- RPC: quiz_group_activity_consent / destinations / publish / read。
- publishは現メンバー、現教材relation、コピー記録、現公開版、同意generation、同意日時を検証。問題数は公開版の問題数以下に制限。
- 共有停止でgeneration変更。再ONしても過去の同意世代の投稿は復活しない。退出/教材解除のtriggerで同意/イベントを失効。解除後に同じ教材を戻しても古い投稿を復活させない。
- 既存のprogress summaryと活動イベントは別テーブル。質問・PDF・手書き・履歴の保存構造は変更しない。

## 検証

- npm test: 851件成功の後、並行送信テストを追加（最終統合の件数はリリース報告）。
- 実SQLをPGliteで実行し、匿名/グループ外/コピー違い/古い公開版/不正数値/古い同意/共有停止/退出/教材解除・再追加と重複防止を確認。
- ブラウザ: 同意ボタン、活動表示、共通詳細と戻り先（実Appのhistory/popstateを含む）、OFF、通信失敗後のoutbox再送、同じ結果の再送、Full Appで取り込み済み教材の演習終了後の単一投稿を確認。
- 1問ずつの回答内容をサーバーへ送っていないことはpayloadの許可キー一致でも検証。

## 配信・復旧

Phase 1 migrationに続けて本migrationを適用し、権限を確認してからアプリを配信する。旧アプリは新テーブル/RPCを使用しないので併存できる。アプリロールバック時もテーブルを削除せず保持する。

ブラウザ強制終了など、セッション終了処理が実行されず端末outboxに入る前の活動は投稿されない。回答自体は従来どおり保存される。アプリの同期/リロード保護で復元されたセッションは同じ保存済み回答集合から冪等キーを再作成する。端末outboxは学習バックアップに含めず、復旧端末から意図しない活動を再投稿しない。

回答保存の成功・失敗・再試行中の画面終了も専用ブラウザテストで確認。

本番反映・最終統合テストはリリース報告に記録する。
