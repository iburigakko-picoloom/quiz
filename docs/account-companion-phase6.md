# Phase 6: アカウント・育成

基準: Phase 1 b58ae49 / Phase 6 f6dbbe6。Supabase DB migrationはない。育成データは既存保存キーのままv4へ非破壊移行する。

## 名前・アイコン

`accountProfile.resolveAccountProfile`に表示の優先順位を集約した。

1. `quiz_profiles.display_name`の既存設定（既定文字列であっても上書きしない）。
2. 設定が空の場合のみ、設定済みLINE providerのidentity_dataのname/display_name/full_name。
3. 従来のemail先頭部分、取得できなければ「Quiz Make ユーザー」。

`cloudService.getCloudAccountProfile`はSupabase `auth.getUser()`で現利用者を確認し、本人のプロフィール行を取得、完了時にsessionの利用者も再確認する。auth listener内のSDK lockを避けるため取得開始を次のタスクへ延期する。表示metadataは権限判断には使わない。

設定画面と同期画面は共通の名前と既存`AccountAvatar`を使用。設定画面で「LINEの名前を使う」を押すと編集欄だけを更新し、既存の「表示名を保存」で確定する。LINEプロフィール変更による保存名の自動上書きはない。保存後はイベントで同期画面を更新する。自分のグループ内アバターにもAccountAvatarを使用する。他メンバーの私有LINE identityは取得・公開しない。

アイコンはLINE identityのpicture/avatar_urlのHTTPS値のみ。値なし、認証失敗、不正URL、画像読込失敗時は既定アイコンを維持。独自アイコンのユーザー設定は現行アプリにないため新たな保存形式は作らない。

公式資料:
- https://developers.line.biz/en/docs/line-login/verify-id-token/ （name/picture、profile scope、サーバーでのID token検証）
- https://supabase.com/docs/reference/javascript/auth-getuser （サーバーによるuser取得）
- 既存のOIDC custom:line/custom:quizmake-line、openid profile scopeを維持。実LINE OAuthアカウントのログインは未実施。署名検証をクライアントに作り直していない。

## 育成の共有解答数

ユーザー確認で、問題は食事後にも同じ解答でおやつを使える二重付与だった。名称変更は撤回し「おやつ」タブを維持。新規解答を1問=1残枠で記録し、食事50問分/おやつ25問分を同じ残枠から消費する。

v4へ読み取り移行し、旧food/treatsは既得所持品として維持。旧余りだけ残枠へ移し、過去の付与済み回答を再加算しない。v1/v2には存在しなかったおやつを追加発行しない。DB migrationは不要、保存キーは維持。旧アプリへのロールバックはv4を読めないため禁止。

消費UUIDを保持し、同期受信で既知消費が欠落する場合は両原本を保護して専用画面で育成状態を選ぶ。解答IDと消費IDは両方保持。同じ解答数の並行消費で残高が負になった場合は補充分として表示し、追加回答で返済するまで新規消費できない。異なる移行基準では選択側残高・旧所持品を起点にし、他側の移行前回答は再加算せず、未採用消費のみ減算する。原本は削除しない。

完全バックアップの復元も既知消費台帳を維持する。全体同期では育成解決後に統合した端末データを選ぶ。旧v3端末は消費IDを保存できないため、同期端末を全て更新してから使う必要がある。旧版で既に行われた個別消費を推測で復元しない。

## 共有解答枠の追加検証

- 単体: 50問→食事後おやつ不可、25問→おやつ、共有枠の保存/再読込、同一回答ID再送、v1/v2/v3移行と既得所持品、負債返済、異なるmigration baseline、旧所持品並行消費、統合済み端末からの追加回答、イベント冪等性。
- 実IndexedDB: 同時クリックの排他、保存失敗で未消費、競合中停止、専用解決後再開、古い完全バックアップ復元でも既知消費保持。両原本と消費台帳は原本ストア/通常outboxで保持。
- Delta: 同額の異なる消費UUIDを検出、受信cursorを進めず両原本保存。解決した古いremote原本は再適用しない。
- Whole: 片側選択による消費消失を検知。専用解決後、統合した端末を選んで送信完了。片側に育成キーがない場合も保護。
- 実App browser: 不正解の回答を含む49→50、結果再表示、食事、芸練習、習得済み芸、名前変更/再読込、320/390/768px。並行消費を専用画面で解決し、補充分25問の表示と両消費操作停止を確認。

同期確認中の原本と通常の選択側原本は削除しない。旧v3で実際に行われた消費はUUIDがないため完全な再構成はできない。移行後も古いアプリを並行使用しないこと。既知消費が戻る受信は停止し、専用解決を経由する。全体同期で専用解決後に再び古いクラウドを選ぶ操作は拒否されるので、統合済み端末を選択する。任意の育成データJSONを汎用原本復元で直接上書きする操作は従来通り拒否される。
